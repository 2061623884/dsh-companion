# Independent runtime and one-time migration

Companion bundles its own public DSH Web runtime and uses an independent home. Desktop processes, configuration and session data remain unmodified; the shared credential store is the exception described in docs/architecture.md. This replaces hidden desktop startup and deliberately gives up live cross-client configuration sharing: the current DSH JSON domain storage has no cross-process write locking and schedulers are host-local.

All VS Code windows using the same Companion home share one named-pipe-owned runtime. The last client disconnect triggers bounded shutdown after a five-second reconnection grace. Configuration and completed historical sessions are imported once, and only previously skipped historical IDs may be retried on later startup. DSH's common credential store is shared in place, so explicit sign-out on either side affects both. A mismatched account platform fails without removing the shared login. WorkBuddy's separate credential files retain their existing read-only adapter: an independent Companion login takes priority; otherwise desktop access is borrowed in memory without copying, refreshing or deleting it. Configuration, domain storage and history remain independent.
