# Independent runtime and one-time migration

Companion bundles its own public DSH Web runtime and uses an independent home. Desktop DSH remains unmodified. This replaces hidden desktop startup and deliberately gives up live cross-client configuration sharing: the current DSH JSON domain storage has no cross-process write locking and schedulers are host-local.

All VS Code windows using the same Companion home share one named-pipe-owned runtime. The last client disconnect triggers bounded shutdown after a five-second reconnection grace. Configuration and completed historical sessions are imported once, and only previously skipped historical IDs may be retried on later startup. Since 0.3.3, an existing independent Companion WorkBuddy login retains priority; otherwise desktop access tokens are read-only borrowed in memory. Desktop credentials are never copied, refreshed or deleted. This limited live read does not share configuration, domain storage or history, and cannot autonomously renew an expired desktop token.
