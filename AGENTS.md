# Development rules

Keep RuntimeConnection, EditorContext, ReferenceController and SidebarView cohesive. Runtime bootstrap and one-time import belong behind RuntimeConnection; DSH UI objects and DOM assumptions belong only in the private browser adapter. Test observable behavior through module interfaces.

Ship a pinned public DSH Web runtime and Node inside the VSIX. Use an independent DSH_HOME under globalStorageUri; never start, stop or change desktop DSH apart from the shared credential store. Like the Codex extension and its CLI, Companion's runtime reads and writes desktop's `.credentials.yaml` through the pinned local store (cross-process lock, watched reloads): sign-in, sign-out and key changes apply to both; never copy credentials into Companion home. Import compatible models and historical logs/attachments once without changing their source; do not import automation or connectors. When Companion has no independent WorkBuddy login, use desktop WorkBuddy access tokens read-only in memory; never copy, refresh, overwrite or delete the desktop WorkBuddy files. Follow desktop token updates and report expiry without initiating login or refresh. One named pipe owns one runtime per data directory; all VS Code windows share it. Stop and save after the last client disconnects, with a five-second reconnection grace. Never log credentials, authorization headers or source text. Network/user input are validation boundaries; preserve safe error codes, do not swallow unexpected failures or silently fall back.

Make the minimum required change. No speculative providers, remote modes, abstractions or unrelated refactors. Build/typecheck/tests and native integration acceptance are distinct; record unverified cases. Do not publish or push without an explicit request.

Keep integration user-independent: derive locations from the current environment/VS Code context, use synthetic fixtures, and keep provider-specific authorization in runtime adapters. Before publication inspect tracked files, reachable Git history and final archives for secrets and personal information; never commit local account evidence, raw diagnostics or personal machine paths. See docs/privacy.md.
